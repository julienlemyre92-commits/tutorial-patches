# GUIDE continue button suppressed forever by stale-widget guard (Build 300)

- FINDING: Diag tails `2026-10-07_16-43-04_GUIDE_diag.txt` and `2026-10-07_16-44-05_GUIDE_diag.txt` (mystery TI client, runtime Build 300, stage GUIDE, varp-281=2) show a per-second cycle: the broad scan PROMOTES 'Click here to continue' (162:44, bounds x20/y619) and then Build 318 suppresses the click: "STALE-231:5-SUPPRESSED -- dialogOpen=false, text empty, but continueVisible=true (continueRect=present) -- stale widget from completed transaction (lastCompleted=null) -- suppressing in tick-wait path, waiting for changed candidate/text/varp". 28 suppressions per tail; the tick loop never clicks, and the guide intro never advances past its first continue.
- ROOT CAUSE: the staleness judgment fires even with lastCompleted=null -- i.e. it declares the visible continue a leftover of a *completed transaction* when NO transaction has ever completed on this session. The wait condition ("waiting for changed candidate/text/varp") can never be satisfied, because the click that would change the state is exactly the action being suppressed. Self-locking predicate: wait-for-change && block-the-change.
- SUGGESTION: only treat a visible continue as stale when lastCompleted != null AND the candidate's bounds+text match the one clicked in that completed transaction; otherwise click it. Also bound the suppression in the tick-wait path (e.g. force the click after N consecutive suppressions) and log the forced click so the diag shows it.
