## Findings

- **[m] VERIFY_OPEN proximity shortcut can bypass the door-open proof.** `dist(pos, manorExitOutside)<=1 -> PROVED` fires from any tile within Chebyshev/Euclidean-truncated distance 1 of (doorX, doorY+1) -- including (doorX-1, doorY), a plausible walkStep stop tile west of the door, where WorldPoint.distanceTo truncates sqrt(2) to 1. In that case PROVED fires on the first VERIFY tick without the door ever opening and without crossing. Consequence is bounded and diagnosable (bogus PROVED -> main flow re-triggers DISCOVERY, but the same door no longer qualifies since x >= player.x+2 fails -> picks another door or HOLDs "no east-side live Open door"), never a silent hang. Suggest gating PROVED on the door proof first, or dropping the shortcut.
- **[i] Upstairs start still HOLDs.** Player on manor plane 1/2 -> isManorGroundFloor false -> walkTo fails -> ROUTE_DOOR_RECOVERY -> HOLD "no forward closed door" -> next reload converts via recoverManorHold -> not ground floor -> RESTART_QUEST_FLOW -> retry -> re-HOLD. Cycles only across hot reloads (not autonomous). Stair descent is out of scope for this build, but Alex's ~03:50 EDT report parked the account at (3110,3367,2) -- if the Doric run starts upstairs, expect this HOLD, not a descent.
